# decoder-helper에서 가져온 경험 (필요할 때만 읽기)
원본 저장소는 이 PC의 `E:\GitHub\decoder-helper`(CLAUDE.md, tools/table/README-PC.md). 같은 사용자가 같은 방식으로 일함.

## 일하는 방식 (그때 굳어진 것)
- 목표를 숫자 하나로(decoder: 정답 찾기까지 평균 클릭 수 → 여기: 적립 시뮬 연수익). 판단 기준은 **실제 기록**.
- 실험은 끝까지: 시험할 수 있는 건 다 해 보고 수치가 가장 좋은 쪽. **같은 데이터로 비교**해야 같은 기준.
- 코드는 PC에서 한 번에 돌게(`master.sh` = 받기→학습→계산→검증→통과 시 main 머지, 약 5~6시간). 진행 줄 한 줄 덮어쓰기, 단계마다 시각·남은 시간, 끝나면 사용자에게 "올릴까요?" 확인. 클라우드에서는 `--no-fetch`로 소규모만.
- main 반영은 사용자 확인 후에만. 새 기록이 들어오면 "편향이 같은 방향인지" 확인, 특이 행(예전 버전·장난·중복)은 짚어 줌.

## 검증·과적합 교훈
- 점수 = **학습에 안 쓴 데이터**로 잰 값만 믿음(decoder: 5겹 교차검증 로그우도). 학습한 데이터를 다시 재생하면 외운 효과로 좋게 나옴 → 공정 비교는 두 버전 모두 새 데이터로.
- 조합별 보정(✕ 조합마다 칸 보정)은 처음엔 좋아 보였다가 **과적합으로 탈락**. 벌점(LAM 0.75, 같은 묶음 LAMG 10)으로 눌러서 안정화.
- 419판에서 통과한 계수가 479판에서 탈락한 적 있음 → 데이터가 늘면 **다시 시험**. 탈락한 건 "넣지 않은 것" 목록에 남겨 반복 금지.
- 시간에 따라 규칙이 바뀔 수 있음 → 시즌/시기별로 4등분 비교해서 패턴 유지 확인. (여기서는 시간 순서 검증이 같은 역할)
- 이번 프로젝트에서 같은 모양의 실수가 실제로 있었음: 미래 정보가 학습에 샘(장기 보유 종목 최종 수익), 야후 월봉 3개월 간격 오류. **좋은 숫자가 나오면 먼저 의심**하고 원인을 찾을 것.

## Apps Script·배포
- 수정 후 **배포 관리 → 연필 → 새 버전**으로 배포해야 URL 유지("새 배포"는 URL이 바뀜).
- 기록은 구글 시트에 쌓고, 사이트는 웹 앱에서 읽음. 개인정보·키는 저장소에 넣지 않음.
